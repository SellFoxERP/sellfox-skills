## 一、模板骨架

```markdown
> ⚠️ 演示数据，非真实经营数据（指纹：…）      ← 仅命中演示指纹时出现

# 📊 每日经营日报 | {yyyy-MM-dd}

## 今日结论与行动

### ✅ 今日行动建议
- {数据缺口翻译成动作，2~4 条；无缺口写「无待办，数据完整」}

### 🔴 今日红线（≤5 条，含归因线索）
- **{异常名}**：{昨日值}（基线 {基线值}，偏离 {±x%}）
  - 归因线索：{归因路径}

### 核心指标
> 数据可用度：核心 6 项中 {N} 项可用；主要缺口={一句话或「无」}

| 指标 | 昨日 | 币种/口径 |
|---|---|---|
| GMV（销售额） | … | USD |
| 订单量 | … | — |
| 毛利 | … | USD |
| 毛利率 | …% | 利润口径 settlement |
| ACOS | …% | adCost/adSalePrice |
| CVR | …% | orderNum/sessions |

> ⚠️ 一句话结论：…

## 分项明细（七步检查）

### STEP 01 账户 / 订单 🔴 P0
- 退款数 / 退款金额 / 退货数
- 订单异常下钻样本：N 条（抽样，非全量）
- ⚠️ 账户健康 / 绩效通知 / 买家消息 — 需人工核查

### STEP 02 销售 / 流量 🔴 P0
- GMV / 销量 / 基线方法（30 天切片）
- MSKU 级销量环比为宽表指标（custom-report-analysis 承接）— 需人工核查

### STEP 03 广告
- 广告花费 / 广告销售额 / ACOS
- 活动状态：enabled / paused / archived / unknown
- ⚠️ 高花费零转化：…
- 说明：servingStatus 的 BUDGET_CAPPED 不作判定条件

### STEP 04 库存
- 可售天数/库龄分桶/补货建议为宽表字段（custom-report-analysis 承接）— 需人工核查

### STEP 05 转化
- Sessions / 订单 / CVR；购物车占比偏低项
- 说明：02 看结果、05 看过程

### STEP 06 售后
- 退款率 / 退款数 / 退货数 / 新增差评数
- ⚠️ 评论原文 — MCP 仅有聚合指标

### STEP 07 政策（无法自动化）
- 状态：⚠️ 需人工核查
- 政策合规 / 绩效风险 — MCP 无此接口

## 附录（样本与数据说明）

### 订单异常样本（已脱敏）
- {amazonOrderId}（{店铺}）标记：退货/退款/取消 … buyerEmail: ab***@x.com buyerName: 张*
> 已脱敏：buyerEmail / buyerName 已掩码。

---
### 数据说明（口径 / 覆盖范围）
- 利润口径 / 币种 / 业务日边界 / 数据源 / 数据截止

### ⚠️ 口径降级            ← 有降级时
### ⚠️ 取数覆盖范围（截断披露） ← 有截断时
### 无数据                  ← 有空数据源时
### ⚠️ 本日报未能覆盖        ← 必填
### 参数来源                ← 必填
```

## 二、双读者分层说明

| 层 | 读者 | 内容 | 位置 |
|---|---|---|---|
| **今日结论与行动** | 赶时间只读这层 | 红线清单（≤5）+ 3~6 个核心指标 + 一句话结论 | 顶部 |
| **分项明细（七步检查）** | 逐项排查 | 7 步逐项：指标 + 异常 + 归因 + 建议 | 中部 |
| **附录** | 运营 | 异常 ASIN/订单明细、库存预警清单（PII 已脱敏） | 底部 |

顺序原则（SOP 元原则）：**先风险，后经营；先异常，后优化**。
所以 STEP 01 / 07 的风险项和 STEP 02 的异常要**提到最前面**（红线区块），再展开常规数据。

## 四、不可省略的区块

以下四块**缺一不可**，否则日报失去可信度：

1. **「本日报未能覆盖」** —— 列出 MCP 无数据源的项（账户健康、买家消息、政策、评论原文），标「⚠️ 需人工核查」。
2. **数据说明** —— 利润口径 / 币种 / 业务日边界 / 数据源 / 数据截止时间。
3. **参数来源** —— 阈值、利润口径等的来源（配置命中 / 本次填写 / 默认值），默认值必须显式标注。
4. **截断/降级/无数据披露**（如有）—— 禁止静默。
