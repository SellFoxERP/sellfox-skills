# MCP 发现、执行与结果处理

## 连接与发现

使用客户端已连接的 Sellfox-MCP，名称可能被客户端规范化。连接地址和 Key 由客户端管理，不写入技能、报告或工具参数。未连接时说明需要配置连接；不要自行索要、保存或打印 Key。

三个网关入口的职责不同：

| 入口 | 何时使用 | 如何使用 |
|---|---|---|
| `help` | 不知道业务工具 ID，或原工具不再可用 | 用完整业务问句，包括对象、读写目的、已知范围；`include_schema=true`，`limit` 为 1–10。按返回结果选择工具 |
| `search` | 已知工具 ID，但缺当前完整契约 | `tool_ids` 一次 1–5 个，`detail=true`；这不是关键词搜索 |
| `action` | 已选定工具，有当前完整契约和必要参数 | 传 `tool_id`、`params`、本次 help/search 返回的 `contract_version` |

候选排序不是最终选择。核对候选的 platform、use_when、not_for、operation_type 与用户问题；例如未指定平台的利润问题不能直接选择返回的 TikTok 工具。平台未知且影响工具选择时先确定平台，候选不匹配时细化问句。

业务域文档中的工具 ID 是导航线索，不是固定调用链或可调用性保证。已有当前完整契约可直接执行；`help` 已返回完整 schema 时不再重复 search。目录 `next_cursor` 只用于发现更多工具，不可用于业务分页。

`selection_status=needs_clarification` 时先处理 clarification；`no_match` 时不编造工具。可用更具体的业务描述再发现一次；仍无匹配则说明当前连接未提供能力，并使用用户已有导出文件（如有）。不要把“本次没匹配到”说成“赛狐永远不支持”。

## 构造请求

阅读 `inputSchema`、字段描述、枚举、日期范围限制、分页、输出字段和业务约束。只传 schema 声明的字段；不附加 ctx、凭证、URL、SQL 或代码。版本号不能复制参考文档或旧运行记录。

店铺、商品、广告活动、报表等 ID 从用户已确认值或实时查询结果取得；名称匹配有多个候选时澄清，不取第一条。按工具返回的 call_chain 和 bind 解析依赖；已有可靠 ID 则跳过重复查询。不同工具的 shop_id、shop_ids、shop_id_list 类型不一定相同。

只补问会影响当前任务的缺失信息。既有明确日期、范围、币种和财务口径沿用；“最近”“昨天”等按用户时区转为明确窗口。缺财务口径时可以先做店铺和能力查询，但不要擅自决定结算/发货或汇总币种。

## 读操作、分页与异常

1. 按本次范围读取，保留请求条件及每页的完整业务信封。优先读取 MCP 的 structuredContent；只有 text 时解析其中 JSON。
2. 检查 `status`、`coverage`、分页标记、`warnings`、`output_validation`；单页 complete 不代表全量完成。
3. 按当前契约翻页。重复游标、重复页、返回日期/范围不符或达到任务规模限制时停止，披露已取条数及未覆盖范围；不能把未排序的前 N 条称为 Top N。
4. `partial` 保留成功数据并说明缺口；`failed` 不当业务数据；`unknown` 或缺 status 不进入正常统计。空结果、空值和省略字段不等于 0。
5. 版本失配重新取契约；参数错误按 field_errors 修正。只有明确未执行的请求才可修正重试；其他只读临时错误按 retryable 最多重试一次。契约/结果超预算时缩小批次、页面或范围，只重取失败部分，不无界重试。

响应结构警告保留原值，不能据此声称类型或业务口径已认证。字段转换失败标未知。跨币种分别汇总，只有明确汇率、日期和转换依据时才换算；不平均百分比来计算整体比率。连接数据时使用明确的店铺及商品/活动标识和一致粒度，避免一对多重复计数。

生产分析遇到日期或对象不匹配时停止对应统计。用户明确要求能力演示时可展示返回样本，但须标记实际日期和请求差异，不能将样本解释为真实经营结论。

## 写操作与异步任务

查询、诊断、优化建议均不自动授权修改。需要写入时先给出具体对象、原值、目标值、影响及核验方式。已有用户对这些具体内容的明确授权则继续，不重复确认；模糊的“优化一下”不足以执行批量修改。

执行前读取当前值，按当前写契约只处理批准对象。创建下载任务也有副作用，应确认用户请求涵盖创建任务。任务创建成功后保存返回 ID，按契约查询进度；结果就绪、失败或达到本次等待上限即停止，待处理不能写成分析完成。

写返回 partial/unknown/超时，先逐项核实成功、失败、未知，不重放整批。不确定是否已经提交时不能因为重取了契约就重发。完成后按当前只读能力回读核验；无法回读时写“已提交、未核验”，不声称最终生效。不要把自动回滚当作默认安全措施。

## 交付

按用户问题给出结果，包含：范围/日期/口径、主要发现及依据、覆盖缺口、下一步建议。查询可以直接回答，不强制生成日报。将观察、推断和待核实项分开。

需要保存时使用本次任务独立的本地输出目录，保留工具 ID、请求范围、trace_id、状态及各页警告供核查；不写入密钥。业务明细和原始响应不提交仓库。外发或通知仅在用户要求的范围内进行。

## 本地计算

需要分页汇总、去重、比率或期间对比时，按 [Python 数据处理](data-processing.md) 保存信封、生成计划并执行脚本；计划由助手根据本次契约生成。输出报告不替代上游数据覆盖判断，脚本不发起业务写入。

**子代理取数（优先尝试）**：默认先把上表连同调用纪律（`_shared/SELLFOX_CLIENT.md` §9）交给子代理执行——原始信封只进子代理上下文，主代理仅验收步骤摘要并抽验落盘；客户端不支持/派发失败/摘要不合规时回退主代理直取（兜底路径，行为一致）。
