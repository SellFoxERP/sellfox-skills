# 库存与物流（logistics）

用于 FBA 货件、AWD 库存、物流服务及头程费用。调用遵循 [MCP 流程](mcp-workflow.md)。

## 工具导航

| 需求 | 已知入口 | 注意 |
|---|---|---|
| FBA 在途与货件状态 | `get_fba_shipment_page_list` | 区分创建/更新时间范围，依据当前契约查询 |
| AWD 库存 | `get_awd_inventory_page_list` | 与在线可售库存分开列示 |
| 头程分摊 | `get_fba_shipping_head_fee_page_list` | 核对费用币种、分摊对象与财务是否已计入 |
| 收货地址 | `get_inbound_shipment_destination` | 使用已确认货件编号，地址仅按任务需要展示 |
| 装箱明细 | `get_packing_task_detail` | 需要真实装箱任务标识，不能用货件 ID 替代 |
| 物流商 | `get_logistic_page_list` | 列表不等于报价、物流轨迹或发货能力 |

问句示例：“查看指定店铺在途的 FBA 货件及状态，检查哪些商品仍可能断货。”按当前工具契约发现所需 ID 与分页方式，已有 ID 则直接读取对应范围。

## 库存判断

需要可售库存时联查 [在线商品](orders.md)，需要需求速度时联查 [销售统计](analytics.md) 或已确认的 [报表](reports.md)。同一货件在多个数据源出现时按实际标识去重，不能把入库中、在途与总库存再次叠加。

仅在库存口径和销量窗口可靠时计算覆盖天数；日均销量为零时标无可用需求速度，不强制给无限天数。补货数量需要交期、安全库存、已下单/在途信息；缺项时给条件估算或待补信息。已在途覆盖缺口时可列观察项，不再把零补货数量称为紧急补货。

输出库存/在途快照、风险依据及补货建议，区分确定缺货与信息不足。查询和建议不自动创建采购单、货件或变更物流；若用户要求操作，再用完整问句发现对应写能力。

## 数据处理脚本

库存/货件/装箱应分别建计划。按仓库、状态或店铺分组，数量用 sum，费用用 money；货件明细键必须包含货件和商品/行标识，不将多种库存口径相加。补货公式需要另行明确交期及需求，不由通用汇总器猜测。 按 [Python 数据处理](data-processing.md) 生成本次计划，运行 `scripts/process_data.py`，保留逐页来源和警告。
