# 自定义报表与指标（reports）

用于读取商家已有报表、查询统计指标和管理明确授权的自定义公式。调用遵循 [MCP 流程](mcp-workflow.md)。

## 工具导航

| 需求 | 已知入口 |
|---|---|
| 已有报表详情 | `get_custom_report_page_list` |
| 自定义指标列表 | `get_custom_report_index_page_list` |
| 可用统计指标 | `get_custom_report_stat_index_list` |
| 新增/更新指标 | `add_custom_report_index`、`update_custom_report_index` |

问句示例：“读取我的经营报表，按店铺分析上周销量和利润。”先判断内置统计/财务查询是否已足够，只有需要自定义字段时才进入报表读取。读取报表与编辑指标是两类授权。

## report_id 的处理

1. 有当前账号已验证的选择则复用，并核对本次读取范围；没有 ID 时自动发现，不让商家手填、修改 YAML 或先新建报表。
2. 用 help 查找报表目录能力并核对用途。2026-10-15 当前连接的 reports 域有 5 项能力，未发现独立报表目录；这个结论只针对当时目录，不限制未来能力。
3. 没有独立目录时，获取 `get_custom_report_index_page_list` 当前契约并查询，不传未知 report_id_list。按契约读取分页和共享范围，提取实际 `data.rows[].reportList[].reportId` 与 `reportName`，按 ID 去重。该关联路径已实际返回报表名称与 ID，不要用 indexId 或任意 id 替代。
4. 关联清单不是完整目录：未关联自定义指标的报表可能不出现。部分页失败时保留成功页候选及警告，不能宣称全部报表或没有报表。响应字段变化时重新核实，不套用历史样例。
5. 根据用户指定名称、用途、范围筛选；同名多 ID 或多个合理候选时只让商家选报表名称。匹配唯一后用详情查询核对字段、粒度、日期和币种，适用才自动采用。仅凭排名第一、仅一条关联或名字带“利润”不足以选定。
6. 无候选、权限失败、数据为空或用途无法验证时，继续 [销售统计](analytics.md)、[财务](finance.md)、[在线商品](orders.md) 或 [物流](logistics.md) 的可得数据，说明缺口，不转而要求手填 ID。空 rows 只证明本次可读取，不能证明用途和指标齐全。

本通用技能可独立运行，不要求持久化脚本。仅在本次任务中使用 ID 就能查询。若完整技能包已安装且用户要求记住选择，可读取共享 `ONBOARDING.md`：仓库/市场安装位于 `../_shared/ONBOARDING.md`（相对技能根目录），批量安装位于 `../_sellfox_shared/ONBOARDING.md`；按其中验证流程保存。独立安装没有该资源时，保留会话上下文即可，不伪称已永久保存。换账号后重新验证权限，不跨账号自动复用旧 ID。

## 指标定义与修改

读取当前统计指标与自定义公式，明确分子分母、单位、币种、维度和过滤条件。统计指标目录可能为树状，按当前输出结构遍历；无总数/翻页依据时标覆盖未知，不把节点数上限当作完整性证明。

先给出公式差异及受影响指标，确认用户意图与权限后才新增或更新。共享指标可读不代表可写。新增前检查同名/同义项，避免重复；更新前保留原公式。只修改已批准字段，回读验证，不自动创建报表或删除指标。

## 数据处理脚本

报表宽表的 rows_path 与字段依当前契约生成计划，指标公式不作为 Python 代码执行。关联 reportList 的提取继续用共享 merchant_setup.py candidates（完整包可用）或按上述已验证路径解析；通用汇总器不把嵌套 reportList 当指标数值。 按 [Python 数据处理](data-processing.md) 生成本次计划，运行 `scripts/process_data.py`，保留逐页来源和警告。
