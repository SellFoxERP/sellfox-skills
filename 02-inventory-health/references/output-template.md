# 输出模板（output-template.md）

渲染层（`scripts/render.py`）按本模板输出。**「数据说明」区块为必填，不可省略**——
它决定了报告的可信度。

## 输出结构

```markdown
[演示水印（命中演示环境指纹时）]

# 📊 库存健康体检与补货建议 | {日期}

## 核心结论
- 🔴 P0 来不及：N 项 ｜ 🟠 P1 有缺口：N 项 ｜ 🟡 P2 预警：N 项 ｜ ✅ 健康：N 项 ｜ ❓ 数据不足：N 项
- 滞销清理：N 项
[- ⚠️ 口径降级：…（未配置报表 ID 时）]

## 双向矩阵（断货 ↔ 滞销）
              高销量
   ① 紧急补货 ( n) │ ② 健康 ( n)
  ─────────────────┼──────────────────→ 库存水位
   ③ 滞销清理 ( n) │ ④ 低效观察 ( n)
              低销量

## 补货建议单
（见下）

## 象限明细
### ① 紧急补货（N 项）
### ② 健康（N 项）
### ③ 滞销清理（N 项）
### ④ 低效观察（N 项）

---
## 数据说明   ← 必填
```

## 补货建议单（列定义）

| 列 | 来源 | 说明 |
|---|---|---|
| MSKU | `msku` | 归一化后取首个值 |
| ASIN | `asin` | 同上 |
| 可售天数 | `availableDays`（降级自算时标注） | 官方口径 |
| 到货周期 | `lead_time.yaml` 解析 | 含旺季系数 |
| **周期来源** | 解析层级 | **配置(供应商) / 配置(SKU) / 配置(运输方式) / 本次填写 / 默认值⚠️** |
| 在途 | 四个在途字段求和 | 全缺 = **无数据**，不写 0 |
| 缺口 | `v*(L-d) - inb` | 仅 P1 计算；≤0 判「无缺口」，clamp 到 0 |
| 建议补货量 | `max(缺口, suggestNumSum)` | P0 用 `suggestNumSum`；**恒 ≥ 0**，负值视为无缺口 |
| 紧急度 | 判定结果 | P0 / P1 / P2；缺口≤0 的行降级为 P2/健康，不列 P1 |
| 负责采购 | **需人工指派** | MCP 无采购人字段，不编造 |

> 列为「无数据」的行不得填 0 —— 0 与「没拿到」是两回事。

## 数据说明区块（必填）

```markdown
---
## 数据说明
- 数据源：赛狐 ERP ｜ 涉及工具：get_online_product_page_list, get_fba_shipment_page_list, …
- 报表窗口：30 天 ｜ 截止：{日期} 23:59
- 币种：售价口径 USD ｜ 成本口径 CNY（跨币种不直接相减，换算须标注汇率来源与日期）
- 取数覆盖范围（含截断披露）：
  - custom_report: 本次共取回 187 行（未截断）。
  - fba_shipment: 无数据
- **本次运行警告**（如有）：到货周期未命中配置的 MSKU 清单 / 演示环境提示

### ⚠️ 本技能未能覆盖（需人工核查）
- 采购下单 —— 赛狐 MCP 无采购接口，本技能只出建议
- 安全库存修改 —— 只能读，不能改
- 长期仓储费金额 —— 未配置费率时需人工核查
- 供应商 / 采购负责人 —— 需人工指派
- 每 SKU 的供应商/运输方式映射 —— MCP 不返回，需人工维护
```

## 写作要求

- 用**祈使/直述**语气，先给结论（管理层只看"核心结论"够用），再给明细。
- 每个 P0/P1 行都要给**动作**（空运/调拨/暂停广告/下单），不只报数字。
- 「需人工核查」是**显式信号**，不要用留空或 0 代替 —— 留空会被误读成"没问题"。
- 演示环境数据**必须**在顶部警示，不可当真实经营数据。
