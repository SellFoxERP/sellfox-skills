# 自动发现与复用报表（专项技能共用）

需要自定义字段时由助手查找报表并取得 report_id，不让商家编辑 YAML、手填 ID 或为首次使用新建报表。内置订单/利润/商品查询不依赖 report_id，不为这些任务触发初始化。报表用途：daily_ops（经营/流量/广告/评论）、inventory（库存/在途/库龄）、profit（成本/赔偿/结算）。

## 先检查已有选择

定位当前技能的共享目录，运行 `<共享目录>/scripts/merchant_setup.py status`（Python 3.10+）。它不联网、不写客户端配置、不读取 Key。

- `verified` / `legacy`：已有选择，在当前账号和本次范围验证可读性后复用；不把旧验证当作永久权限或完整字段认证。
- `deferred`：用户明确选择简版，继续简版，不重复询问或自动保存新选择；用户要求重新查找时再进入发现流程。
- `unset` / `auto_discover=true`：执行下面的自动发现；不再询问“现在配置 / 暂不配置”。`prompt=false` 表示不要求手工配置。
- 配置损坏：保留文件及备份，说明问题；可继续本次只读发现和简版任务，不覆盖损坏文件。

## 自动发现 report_id

1. 按 [MCP 流程](SELLFOX_CLIENT.md) 用 help 发现“列出我可用的自定义报表名称和 ID”。核对工具用途，不把报表详情的 page_list 当成目录。若当前连接确有独立目录工具，使用其当前契约读取、分页和匹配。
2. 若没有独立目录，取得 `get_custom_report_index_page_list` 的当前完整契约。它无需 report_id；不传未知的 report_id_list，不先用 index_name 缩小到某个指标，不默认只查“我的”而遗漏共享报表。share_status 的省略/分开查询行为以当前契约为准；发现只读共享关联不授权修改共享指标。
3. 按契约分页，提取实际 `data.rows[].reportList[].reportId` 和 `reportName`，按 ID 去重，保留同一 ID 的不同名称。该路径已在连接实测，但未来字段变化须重新核实。indexId 是指标 ID，不是报表 ID；不要取任意 id 字段或示例值替代。
4. 每页完整业务信封落入本次任务 out 目录。可以运行：

   ```bash
   python <共享目录>/scripts/merchant_setup.py candidates --input <第一页信封.json> <第二页信封.json>
   ```

   输入也可为含 request/response 的验证记录。脚本只提取候选、去重并保留分页/失败/警告证据，不联网、不选第一条、不写配置。只消费 complete/partial 的有效指标列表，failed/unknown 中即使带 rows 也不作为候选。
5. 关联清单**不是完整报表目录**：未使用自定义指标的报表可能不会出现。分页失败、覆盖未知或达到任务规模上限时保留已发现项并说明范围；不能称“账号没有报表”或“已列出全部报表”。不重试 retryable=false 的失败。

## 自动匹配、验证与降级

- 用户已指明报表名称时按名称匹配并核实 ID；同名不同 ID 要消歧。
- 用户只说“日报/利润/库存”时，先按名称和已知元数据筛选，再小范围读取候选，核对任务所需字段、粒度、日期、币种。名称相近或仅一条关联记录不足以证明用途正确。证据足够且匹配唯一时自动采用，不让商家再提供 ID。
- 多个仍合理的候选时，仅展示名称、用途和可得维度，让用户选择报表；不要求复制数字 ID。缺名称时可显示已发现标识供区分，但不要求手填。
- 无候选、接口失败、未匹配用途或用户不想选择时，继续已有内置查询/简版，说明缺少的字段。没有 ID 不属于安装失败；不把“创建报表并回填配置”作为默认补救。
- 自定义指标治理只有用户指定报表范围时才需要报表 ID；找不到目标不应自动扩大成全部指标的写操作。全局只读盘点可继续，并说明范围。

## 验证后由助手保存或本次使用

用 `get_custom_report_page_list` 的当前完整契约，传自动发现的 ID 及本次日期、范围等必填条件。只读验证失败、unknown、partial 或响应 ID 不符时不覆盖旧选择。空 rows 仅证明可读，不能仅靠空结果认定用途匹配；不自动将未经字段验证的候选绑定到某用途。

明确匹配用途且验证通过后，专项技能由助手保存选择供计算脚本读取（用户明确仅本次使用时不要持久化）。证据来自实际请求和完整响应：

```json
{
  "request": {
    "tool_id": "get_custom_report_page_list",
    "contract_version": "本次契约版本",
    "params": {"report_id": "自动发现的ID"}
  },
  "response": {"完整业务信封": "保留实际返回的所有字段"}
}
```

以上只是格式示意，实际 request 必须包含已调用的日期等全部参数。不要自行生成成功响应。

运行 `merchant_setup.py save --kind <daily_ops|inventory|profit> --id <ID> --evidence <证据文件>`，再运行 status，并告知所用报表名称和仍缺字段。脚本检查验证证据、备份旧值并原子保存；用途、字段及日期核对由助手完成。不要把同一 ID 未经验证保存为所有用途。参数应安全传递，不把商家文本当 shell 代码。

选择“暂不使用增强报表”时可运行 `merchant_setup.py defer --kind <用途>`；仅在用户明确选择后保存。接口失败不等于用户选择暂缓，不能写 deferred。

本次使用而不保存时：通用技能直接传 ID；专项脚本支持 `--report-id` 时使用该参数，否则可在本次独立输出目录建立临时 reports.json，以 `SELLFOX_USER_CONFIG_DIR` 仅对本次子进程生效，验证方式同上，不修改真实用户配置。无需商家设置环境变量。

## 兼容与账号隔离

用户选择保存在主目录 `.sellfox-skills/config/reports.json`，跨版本保留。读取优先级：显式 `--report-id`（支持时）> 独立用户配置 > 旧 reports.yaml。默认 YAML 保持空值用于兼容，不是商家必须填写的部署前置。

一个系统用户默认共用一套选择，切换 MCP 账号后必须重新验证，不能跨商家自动复用旧 ID。管理员可用 SELLFOX_USER_CONFIG_DIR 隔离账号；测试始终使用临时目录。持久化只保存报表选择和暂缓状态，不保存 Key 或完整业务明细。
