# 报告文案规范（面向商家）

> 适用范围：全部 13 个技能的报告出口（**HTML 即报告、唯一文件**；渲染层内部仍以 Markdown 为单一真源）。
> 原则：**报告是给跨境商家看的商品，不是给工程师看的日志。** 诚实披露不动摇，
> 但表达要让人三分钟内知道"发生了什么、我该做什么"。

## 一、分层结构（各技能报告通用）

1. **水印/警示**（仅演示/样本数据时）——第一行；
2. **结论与行动**：一句话结论（真实生成，禁止占位文案）+「今日/本期行动建议」
   （把数据缺口翻译成动作：去哪配、重跑什么、找谁）；数据可用度一行
   （"核心 X 项中 Y 项可用；主要缺口=…"）；
3. **主体**：指标表/榜单/归因——成列表格，摘要优先；
4. **复核明细（机器证据）**：行级原始字段、note、来源——供追溯，放在主体之后；
5. **数据说明（技术附录）**：口径、覆盖、错误码、工具名、配置文件名**只允许出现在这里**。

## 二、语言规则

- **正文只用业务语言**。字段名、工具函数名（`get_*`）、错误码、配置文件名
  （`reports.yaml`）、内部参数（`baseline=window_field`）不得出现在结论/主体区；
  需要引用技术事实时翻译（"宽表取数失败（错误码见数据说明）"）或移入附录。
- 免责/边界说明**全文一次**，不逐行重复；表格下方一句话收纳。
- 店铺显示**名称**而非 ID（best-effort 映射，映射不到显示编号并注明）。

## 三、数字呈现

- **率值一律百分比**（0.3265 → 32.7%），禁止裸小数；
- **率的变化用百分点 pp**（23.0% vs 21.5% → +1.5pp），禁止相对百分比
  （+7.0% 必被误读为 7 个点）；金额变化才用相对 %；
- 金额千分位两位小数，带币种；占比列必须写明分母口径（如"占销售额"），
  禁止无业务含义的分母（如桥接净额）；
- 缺数据渲染「无数据（非 0）」；快照/单窗口模式不渲染基期列。

## 四、图表与格式

- Markdown 的 mermaid 图在 HTML 出口中转为紧凑数据表（共享转换器已实现），
  不得让商家看到 chart 语法文本；
- 列全空（如全「不适用」）时整列隐藏；「未知」类占位用「—」；
- 空提案/空清单时直说原因与下一步（"绩效缺失，本次不出提案，先做 X"），
  不渲染空表格与模板噪音。

## 五、自检口径（评测四维 ③ 的补充判据）

出现以下任一即判文案缺陷：占位文案出现在成品 ｜ 正文区出现工具函数名/配置文件名 ｜
率值裸小数 ｜ 率变化用相对 % ｜ 逐行重复同一段免责 note ｜ 裸 JSON 对象出现在
商家视图表格 ｜ 快照模式渲染基期列 ｜ 占比列无分母口径。
