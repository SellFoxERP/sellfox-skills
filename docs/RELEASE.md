# 发布者说明

本说明供维护者准备 GitHub 发布。技能面向兼容的 AI 客户端，不限定 WorkBuddy；发布和安装不会自动授予生产写操作权限。

## 发布内容

提交 `01~10-*`、`_shared`、`scripts`、`tests`、`docs`、`.github`、`.gitignore`、README、INSTALL 和可选依赖说明。
通用技能和十一个专项技能是一个批量安装产品，共用配置。Release 附件由 `scripts/build_release.py` 生成，只有一份完整安装 ZIP 和 SHA256SUMS，不提供逐技能安装包。

以下内容只保留本地，**不对外发布**：

- `_internal/`：旧客户端、内部迁移/交付资料，含私人路径和内部测试地址。
- 各技能 `out/`、`logs/`：原始响应、经营报告和执行记录。
- 本地客户端配置、`.env*`、`local.yaml`、备份文件、Python 缓存与虚拟环境。
- `dist/` 不提交源码 Git；将其中经检查的产物单独作为 Release 附件上传。

`.gitignore` 已排除上述本地内容，但它不能清除历史提交，也不作用于网页拖拽上传。若使用 GitHub 网页上传，使用上述发布白名单；不要直接把本地整个文件夹拖入网页。
市场发布须包含 `.codebuddy-plugin/` 中的两个 JSON 清单；更新插件内容时同步递增两个清单中的插件版本。发布前检查 `git diff --cached --stat` 和暂存内容，不使用强制添加被忽略文件。

## 可重复验收

Python 3.10+，从仓库根目录运行：

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 scripts/audit_release.py
python3 scripts/build_release.py
```

离线测试在临时副本运行，并阻断子进程网络；安装器只针对临时目录验收。不会用商家 Key、改商家配置或调用业务写接口。
GitHub Actions 已配置 Linux/Windows × Python 3.10/3.12 的离线检查，**配置存在不表示云端测试已经运行通过**。

## 内容审查结论与边界

- 发布候选文件未检出所配置扫描规则覆盖的密钥、私人绝对路径或内部测试地址；扫描不是穷尽性泄密保证。
- 配置中的店铺、报表、目标、汇率保持空值或注释示例；测试只含合成数据。
- 文档已区分本地计算与可选飞书联网，说明广告/指标修改授权及外部素材/评论依赖。
- 参考字段来自历史资料，只作索引；当前契约、响应警告与覆盖范围优先。
- 合规检查是规则提示，不代表平台审核通过；上架包和经营报告都需要商家结合实际数据判断。

## 客户端适配与验收边界

安装器通过 `--skills-dir` 适配不同客户端的技能目录；MCP 配置由客户端管理。WorkBuddy 另支持市场中一次安装十二个技能；安装器保留其默认目录以兼容已有用法。市场清单及隔离安装已通过随附 CLI 验证，图形界面自动触发仍需商家试用确认。不同客户端的发现、自动触发、文件权限和模型执行表现需分别验收，发布时不能把离线脚本测试表述为“所有客户端全流程认证通过”。建议首个 GitHub Release 标注为预发布，并附本仓库验证报告，完成商家试用后再调整发布标签。
