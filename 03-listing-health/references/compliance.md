# 合规（compliance）—— 只提示，永不写入

> 何时读：需要给出合规/政策风险提示时。
> 定位：照搬亚马逊官方 `listing-compliance` 的「pre-write advisory gate, never writes」——
> 合规检查**只输出风险提示，不做任何修改**，也不假装掌握政策细节。

## 为什么单独成一篇

合规判断依赖**账户健康、绩效通知、政策公告、商品合规文件**——这些赛狐 MCP **全部拿不到**。任何「本 Listing 违反政策 X」的结论都会是编造。所以本流程的产出上限是「**提示需要人工去后台核查哪些方面**」，不是「判定违规」。

## 能给什么

基于**可读到的 Listing 字段**，做低置信度的**提示**（不判定违规）：

| 提示点 | 依据字段（来源） | 说明 |
|---|---|---|
| 长期不可售/被删 | `onlineStatus`（`get_online_product_page_list`） | 可能是政策原因，但不确认 |
| 评分/差评异常 | `rating` / `lowReviewNum`（online / custom） | 提示核查买家反馈，**非政策判定** |
| 标签缺失 | `labels` / `productLabelList`（online） | 缺内部合规标记（如证书/质检）时提示补 |

## 明确不做

- ❌ 判定「违反某条 Amazon 政策」——无政策数据源。
- ❌ 读取或改写 Listing 的合规文案、认证字段——MCP 无此能力。
- ❌ 输出具体违规条款编号——会编造。

## 输出模板

```
⚠️ 合规提示（低置信度，需人工核查，非违规判定）
- ASIN B0XXXX：连续不可售 N 天，建议登录卖家后台「账户健康 / 绩效通知」确认是否政策原因。
  依据：onlineStatus（get_online_product_page_list）
  本技能无法核实实际政策状态。
```

## 铁律

1. **永不写入**。
2. 所有结论标 **⚠️ 需人工核查**。
3. 用「提示/建议核查」措辞，不用「违规/违反」措辞。
