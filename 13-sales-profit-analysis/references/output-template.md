# 输出模板（六段）与反模式

①② 必给，③~⑥ 按问题取舍——问排名就给榜，问结构就给占比，问原因就给归因，
别为凑格式塞无关段落。**第一行恒为口径行。**

```
① 口径=settlement｜币种=USD/CAD 分开未折算｜窗口=20261007-20261020 vs 20260923-20261006
        ｜粒度=店铺+ASIN｜成本层级=先入先出｜覆盖=totalPage 已翻完｜无数据站点已单列
        （口径行不可省：换个口径就是另一个数，读者得能照它自己复现）
② 结论：先给方向（是升是降，别顺着用户的错误前提答）再给额与率
③ 结构：桥接七项 Δ 表（同层不双计）+ 残差说明
④ 榜：赚钱/亏损 Top，ASIN 榜标"与站点层不同基，仅排序"
⑤ 归因：有几条报几条（1~5 条都合法），每条 = 根因 + 证据字段与数值 + 🟢🟡⚪ + 方向（L4）
⑥ 局限：仅确有缺失/口径冲突/未覆盖时输出
```

## 渲染层固定要求（render_report.py 实现）

1. 演示/样本数据（MOCK-/SHOP-DEMO-/「演示」指纹）→ 报告首部水印行
   「演示/样本数据指纹（X）：结果不作为经营结论」；
2. 数据说明区块：失败步骤 error_code、覆盖矛盾（coverage vs 分页标记）、残差、
   信封 warnings、剔除的零销售行数——failed ≠ 无数据，无数据标「无数据（非 0）」；
3. 涉及订单明细时买家字段（buyerEmail/buyerName 等）先过共享 PII 脱敏；
4. 整体率一律标【自算】（Σ分子÷Σ分母）。

## 反模式（出现即判质量错误）

拿默认空串跑口径 · 对行级率求平均 · 组合字段与单项放同一张 Δ 表（双计） ·
固定方式与先入先出同表对比 · 把零销售行的哨兵率值当真值排名 · 报"净利率"却不列扣减项 ·
只发一次 `desc` 就说"没有亏损品" · 十几行靠口算 · 把 ⚪ 升成 🟡 凑归因条数 ·
顺着"利润下滑了"的前提硬找下滑 · **变化归因只看区间聚合就下结论**（停投与单日贷项
只有日序列看得见） · 把停投写成"成本优化" · 把单日贷项当经营改善且不报剔除后的 Δ。
