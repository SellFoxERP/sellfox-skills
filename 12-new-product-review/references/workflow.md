# 新品复盘流程

1. 确认平台、店铺、新品定义、截止日及目标。默认提出按上架时间 openDate 观察；商家采用开售/首单时间时显式改口径，不混用。7/14/30/60 天是观察窗口，不是统一达标线。
2. get_online_product_page_list 可获得 openDate、firstOrderDate、firstSaleDate、7/14/30 天销量/销售额/广告花费及当前库存。滚动 7 天销量不等于上市前 7 天销量，跨窗口不得直接比较总量。
3. 要复盘上市首 N 天，使用 get_product_analyze_list 按商品和确切窗口查询；从当前 fields 契约选择销量、转化、广告等字段。生成 plan 前逐项核对字段映射：metrics 的每个字段键（field/numerator/denominator）必须与信封 fieldsMap 及契约 output_fields 核对一致（名称、层级、单位含义）后才写入计划；请求了但 fieldsMap 未返回的字段不得进 metrics。误配（如把计数字段当比率分子分母）会产出 status=ok 的错误数值而非报错，核对证据（fieldsMap 快照或契约字段说明）随计划保留。详情需要 groupByStr 时从列表真实结果取得。利润用 get_profit_report_by_msku 单独分析，不能按行号拼接；跨域需核对店铺、MSKU、日期与币种及一对多关系。
4. 按同上市年龄及相同观察长度比较。尚未满 N 天标“观察中”，不得以不足窗口判定未达标。上架日期未知/未来则不评阶段；时间戳须先确认业务时区，保留原值和转换说明，不截断猜测。
5. 将流量不足、点击不足、转化不足、广告效率和供货风险作为排查方向。仅在有对应证据时判断。未提供目标时输出表现及待验证问题，不用统一 ROI/销量阈值宣布新品失败。
6. 输出继续观察、调整或考虑止损的建议及依据，不自动暂停广告/下架。新品样本短、广告归因未成熟或库存数据缺失时明确标注。

报告：商品与上架日、上市天数、已达到观察窗口、实际数据窗口、销量、转化、广告、利润、库存、目标及来源、阶段判断、下一步和建议复盘日期。脚本仅计算年龄与证据指标，目标评估由助手按实际窗口完成。

## MCP 与数据约束

使用客户端实际连接的 Sellfox-MCP help/search/action。未知工具先用完整业务问句 help；已知工具缺当前契约再 search（每次最多 5 个，detail=true），已有完整契约直接 action。help 的 limit 为 1–10，版本来自本次连接。响应 failed/unknown 不进入计算，retryable=false 不重试。

店铺 ID 来自实际店铺列表；分页按当前契约继续，单页 complete 不证明全量。保留请求、response、trace_id、coverage 和 output_validation。原始文件存本地 out，不能进 GitHub。金额按币种分组，不将省略值补零。不要求商家提供 report_id；本主题优先内置接口，确需宽表时由助手自动发现并验证。

**子代理取数（优先尝试）**：默认先把上表连同调用纪律（`_shared/SELLFOX_CLIENT.md` §9）交给子代理执行——原始信封只进子代理上下文，主代理仅验收步骤摘要并抽验落盘；客户端不支持/派发失败/摘要不合规时回退主代理直取（兜底路径，行为一致）。
