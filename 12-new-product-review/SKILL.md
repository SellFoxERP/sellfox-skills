# 新品上市复盘

先阅读 [工作流程](references/workflow.md)，按当前 MCP 契约取数并保留完整信封。由助手生成处理计划，使用 [计算说明](references/calculation.md) 和 `scripts/run_review.py` 输出可复核报告；商家无需编辑 JSON。

## 运行环境与路径

需要批量安装包中的 sellfox-business；计算只用标准库。计算脚本实测 Python 3.9 即可完整运行（无 3.10 专有语法；批量安装器仍按 3.10+ 要求分发，两者不冲突）。脚本兼容源码及批量安装目录，不联网，不读取密钥，不执行业务修改。缺组件时重新批量安装完整包。

执行示例（路径由助手替换）：

```bash
python scripts/run_review.py --plan <本次任务目录>/plan.json --out-dir <本次任务目录>/review
```

每次使用新的输出目录。读取 result.json 的各数据集状态，空数据不表示经营正常，退出码 2 表示无可用数据。「无数据」存在两个出口：empty→退出码 0 与 unavailable→退出码 2 可能并存，以 result.json 各数据集状态为准，勿只看退出码。report.html（主报告，附同名 .md 留档）分两层：正文最前「摘要」是商家可读表（`| MSKU | 店铺 | 上架日期 | 上市天数 | 阶段 |`；阶段：窗口内→观察中（第 N 天/窗口 M 天）、超窗口→超龄、日期未知/未来→日期不明）；其后「复核明细（机器证据）」保留行级原始字段与来源，供 AI 复核与追溯。店铺列优先显示店铺名（best-effort 读取数据集同目录或其父目录 shops.json 的 id/name 映射），映射不到时显示编号并在表下加注。助手还须在两层证据之上补充有依据的结论与行动清单。

报告应包含范围、窗口、口径、主要发现、证据、缺口与下一步；不因请求“优化”就修改广告、价格、库存或退款。未知费用符号、币种、分组或日期须先核实。
